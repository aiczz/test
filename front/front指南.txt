> 项目定位：面向大众用户的时令饮食与智能菜谱 App。  
> 当前版本重点：**时令食材推荐 + 菜单推荐 + 菜谱 + AI 助手 + 现有食材管理 + 购物清单 + 个人中心**。  
> 已取消：**实时价格、价格趋势、价格预测、价格雷达** 等功能。

---

## 1. 项目目标

“食时”是一款结合 **AI + 开源** 的手机端饮食助手。

核心闭环：

```text
当前季节
  ↓
推荐当季食材
  ↓
推荐适合的菜谱 / 菜单
  ↓
用户查看做法
  ↓
加入今日菜单
  ↓
生成购物清单
  ↓
AI助手继续提供个性化推荐
```

前端的主要任务不是做复杂的数据分析，而是：

1. 清晰展示时令食材。
2. 清晰展示推荐菜单。
3. 提供菜谱搜索、详情、收藏。
4. 支持“家里有什么食材”管理。
5. 支持 AI 对话和结构化推荐卡片。
6. 支持今日菜单、多日菜单与购物清单。
7. 保持整体 UI 风格统一、清新、温暖、有“时令感”。

# 19. Dio 网络层设计

统一封装：

```text
ApiClient
```

建议：

```dart
class ApiClient {
  final Dio dio;

  ApiClient(this.dio);

  Future<Response> get(String path) async {
    return dio.get(path);
  }

  Future<Response> post(
    String path, {
    dynamic data,
  }) async {
    return dio.post(path, data: data);
  }
}
```

不要在页面里直接到处写：

```dart
Dio().get(...)
```

页面应该：

```text
Page
 ↓
Provider
 ↓
Repository / Service
 ↓
ApiClient
 ↓
FastAPI
```

# 28. Codex 编码要求

Codex 开发时遵循：

## 28.1 不要随意改变 UI 信息架构

底部导航固定：

```text
首页 / 食材 / 菜谱 / AI助手 / 我的
```

首页固定包含：

```text
食材推荐
菜单推荐
```

---

## 28.2 禁止重新加入实时价格功能

禁止加入：

```text
实时价格
历史价格曲线
价格涨跌
价格预测
价格雷达
低价推荐
```

当前产品不依赖实时价格。

---

## 28.3 页面必须组件化

不要写一个 1000+ 行的页面文件。

重复元素必须抽组件，例如：

```text
FoodCard
RecipeCard
SectionHeader
TagChip
PrimaryButton
```

---

## 28.4 不要过度工程化

当前为 3 人、1 个月比赛项目。

不要主动加入：

```text
复杂 Clean Architecture
Bloc + Riverpod 混用
多个状态管理框架
微服务前端逻辑
复杂依赖注入框架
```

保持简单、稳定。

---

## 28.5 所有异步数据必须处理 4 种状态

```text
loading
success
empty
error
```

页面不能因为 API 失败直接崩溃。

---

## 28.6 Demo 优先

为了比赛演示稳定：

- 食材图和菜谱图优先本地缓存。
- 首页允许提供 Mock fallback。
- AI接口失败要有友好提示。
- 网络失败不能白屏。
- 不要把关键 UI 完全依赖实时网络。
