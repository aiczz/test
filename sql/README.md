## 一、目录里有什么

| 路径 | 是什么 | 权利归属 |
|---|---|---|
| `scripts/` | **清洗与建表脚本**（主管道、校验、精选、知识导出） | ✅ 团队自研 |
| `cleaned_v2/` | 清洗 v2 的产出：运行时六表 + 中间产物 + `schema.sql` + 报告 | ⚠️ 数据部分为第三方语料衍生；脚本与报告自研 |
| `catalog_v1/` | **精选 700 道目录**，线上实例实际使用的就是这一份 | ⚠️ 同上 |

| `seasonal_source/` | 时令知识的整理源头 | ⚠️ 同上 |
| `菜谱数据库_交付_20260918 (1)/` | 上一轮交付包（**数字已过期**，保留是为了说明方法） | ⚠️ 同上 |
| `菜谱数据库_V2_数据清洗与关联重构指南_Codex.md` | 清洗与关联重构的完整指南 | ✅ 团队自研 |

**运行时真正读的六张表**（compact 模式）：`ingredients`(8087) · `dishes`(10000) ·
`dish_ingredients`(77886) · `seasonal_calendar`(52) · `seasonal_food`(544) ·
`seasonal_dish_links`(101)。

线上对外提供给用户的是 `catalog_v1/` 精选后的 **700 道菜谱 / 590 个核心食材**。

## 二、数据从哪来

三个来源，各自的授权状态不同，**逐条列在
[`数据授权与再分发边界.md`](数据授权与再分发边界.md) 第一节**：

1. **下厨房公开菜谱语料** —— 菜名、用料、做法、标签（UGC，受限）
2. **《中国食物成分表》** —— 分类体系 + 每 100g 的 36 项营养素（事实性数据，注明出处）
3. **中医食补知识图谱 D2hKG** —— 功效、适用人群、性味、食用禁忌（依上游 LICENSE）

⚠️ **原始语料（约 2 GB）不在本仓库里，也不对外分发。** 这里只有清洗之后的产物。

## 三、想重新构建数据

```bash
# 注意：需要自备原始语料，仓库里没有
python sql/scripts/clean_v2.py             # 清洗主管道
python sql/scripts/validate_cleaned_v2.py  # 清洗结果校验
python sql/scripts/curate_catalog.py       # 生成精选目录
python sql/scripts/export_vector_knowledge.py  # 导出知识文本
```

导入数据库：

```bash
python sql/cleaned_v2/load_to_sqlite.py    # 或 load_to_mysql.py
```

清洗方法、字段含义、每一轮踩过的坑，都写在
[`菜谱数据库_V2_数据清洗与关联重构指南_Codex.md`](菜谱数据库_V2_数据清洗与关联重构指南_Codex.md)
与各子目录的 README / 报告里。
