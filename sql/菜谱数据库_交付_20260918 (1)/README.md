# 菜谱数据库 · 构建说明

> ⚠️ **本文件的数字已过期**（写于上一轮构建，当时食材表是 11,890 行、14 张表）。
> 交付给前后端请以 **`交付清单_给开发.md`** 为准；
> 本文件保留下来是为了说明「数据是怎么清洗出来的」。

从下厨房 62 万条食材名 + 1677 条营养素数据 + 6534 条中医食材，构建出可用的菜谱数据库。

---

## 一、数据来源与各自作用

| 来源 | 提供什么 | 规模 |
|---|---|---|
| `下厨房菜谱/recipe_corpus_full.json` | 菜名、用料字符串、做法字符串、标签 | 150 万道菜 |
| `营养物质组成表/food_composition_full.csv` | **分类体系**（15 大类 / 61 子类）+ **每 100g 的 36 项营养素** | 1,677 条 |
| `中医食补表/D2hKG_Data-main/` | **功效**（704 个）、**适用人群**（76 个）、性味、食用禁忌 | 6,534 条食材 + 939 条功效边 + 9,693 条人群边 |

**关键发现**：《中国食物成分表》的命名是 `标准名（修饰）［别名］`，
例如 `芝麻油［香油］`、`香菇（鲜）［香蕈，冬菇］`、`番茄［西红柿］`。
**必须解析方括号里的别名**才能匹配上，不解析的话覆盖率只有 22%，解析后到 38%。

## 二、构建流程（四步）

```
① clean_pipeline.py         清洗 62 万条食材名
       ↓
② build_main_ingredient.py  建食材主表（分类 + 营养素 + 中医属性，剔除调味料）
       ↓
③ build_dishes.py           建菜品表（菜品 + 用料 + 做法 + 标签 + 营养汇总）
       ↓
④ schema.sql                建 MySQL 表结构
```

### ① 清洗（`clean_pipeline.py`）

622,689 条原始食材名 → **15,459 个中心词**。做法：

- **规则清洗**：剔除工具容器（35,553 条）、说明文字、纯单位、配料标签；拆分拼接名（20,454 条）；别名归一（271 条）
- **中心词推断**：中心词几乎总在名字末尾（`黑山五花肉`→五花肉），所以统计所有名字的末尾 2/3 字词频，高频尾词就是真正的食材词。**词表由数据涌现，不靠手写**

### ② 食材主表（`build_main_ingredient.py`）

**11,890 个食材**（从 15,459 个中心词里删掉 3,569 个调味料）

匹配策略，按优先级：
1. **人工别名映射**（150 条，全部按成分表实际名称核对过）——`番茄`→`番茄（代表值）`、`香油`→`芝麻油［香油］`
2. **精确匹配**
3. **去括号匹配**

**不做模糊包含匹配** —— 上一版这么做，把「或者」「添加」「色素」都配上了，污染数据。食材匹配宁可漏不可错。

同一食材在成分表里有几十个变体（鲜/干/罐头/品牌），用 `_entry_priority()` 选最基础的那条（`代表值` > `鲜` > 简短的 > 带品牌的）。

### ③ 菜品表（`build_dishes.py`）

每道菜产出四张表的数据：

| 表 | 内容 |
|---|---|
| `dishes` | 菜名、简介、**完整用料字符串**、**完整做法字符串** |
| `dish_ingredients` | 每条用料：**原始字符串** + 清洗后名 + **用量** + 关联食材 id |
| `dish_tags` | 标签（已过滤「XX的做法」这类标题标签） |
| `dish_nutrition` | 按用料克数加权算出的整道菜营养 |

**调味料处理**：调味料不进食材表，但在 `dish_ingredients` 里仍然保留，
`ingredient_id` 为空，可以靠 `raw_name` 在 `seasonings` 表里查到。

## 三、表结构（11 张表）

```
食材维度
  ingredient_categories       15 个大类
  ingredient_subcategories    61 个子类
  ingredients                 ★ 主表：名称+分类+28项营养素+中医属性
  ingredient_aliases          别名
  tcm_effects / ingredient_effects      功效
  target_groups / ingredient_groups     适用人群
  seasonings                  调味料字典（明确排除在食材之外）

菜品维度
  dishes                      ★ 主表：菜名+用料字符串+做法字符串
  dish_ingredients            ★ 菜品-用料（原始串+用量+食材id）
  tags / dish_tags            标签
  dish_nutrition              菜品营养汇总
```

完整 DDL 见 `build/schema.sql`。

## 六、已知限制

1. **食材表 11,890 个里，只有 616 个有分类和营养素**。其余是长尾（99% 只被引用 1 次），
   营养覆盖率按引用次数算是 38%。
2. **营养素来自《中国食物成分表》**，是每 100g 生食的值，不等于烹饪后的值。
3. **调味料的边界**：`淡奶油 / 黄油 / 香油 / 橄榄油 / 花生油 / 芝麻酱 / 花生酱 / 蜂蜜 / 猪油`
   目前按「烹饪用油脂/酱料」归入调味料被剔除。如果项目要用它们，移到
   `build_main_ingredient.py` 的 `KEEP_WHITELIST` 里即可。
4. **中医的「适宜人群」是原文文本**（如"一般人群均可食用"），
   没有结构化成标签。要结构化需要额外做一轮规则解析。
5. **烹饪后的营养损失未计算**（如维 C 加热会分解）。要算需要按烹饪方式建损失系数表。
