# 数据质量、事实校验与响应体验优化

本轮本地优化于2026年10月15日完成；未发布到远程服务器。

## 1. 菜谱计时数据与来源

扩展原文时间提取，支持中文数字、半小时、一个半小时、小时与分钟组合、时间区间以及较长中文数字。区间取上界；保留腌制、浸泡等长等待，不再把超过180分钟的原文时间截短。没有明确依据的菜谱继续显示时长不详。

菜谱接口新增duration_source、duration_note，详情页直接说明计时来源。原文提取结果是步骤中最长明确计时，不是完整烹饪总耗时，不能作为整餐按时完成的保证。多个步骤可能串行或并行，目前未进行可靠总耗时计算。

对当前700道本地菜谱进行只读审计：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 可提取明确步骤计时的菜谱 | 396 | 509 |
| 步骤计时覆盖率 | 56.6% | 72.7% |
| 无明确计时的菜谱 | 304 | 191 |

覆盖率增加16.1个百分点，168道菜的提取结果发生变化，包含新增识别和纠正旧计时。以上是自动提取覆盖率，不是人工标注准确率。配图仍使用实际已有映射，有图442道；未虚构配图或份量。

审计输出：`output/optimization-20261014/data-quality-audit.json`。每条待复核记录附菜谱ID、名称、原提取值、新值和原文计时片段。数据表未被修改。

复现：在back目录执行：

```powershell
.venv/Scripts/python.exe scripts/audit_recipe_quality.py --output ../output/optimization-20261014/data-quality-audit.json
```

## 2. 推荐说明的事实门控

模型仍在合法候选中筛选。对模型回答和推荐理由加入保守规则门控：含未核验数量、时长、健康承诺等表达时，改用结构化事实或算法说明，并在推荐流程中标注降级。库存说明继续由后台依据实际登记数据生成。

覆盖普通对话推荐、食材推荐、配菜和首页模型说明，包括首页原有缓存读出的说明。菜谱数量由实际选中结果生成，不再固定声称三道菜或保证荤素均衡、做起来不费事。

这是保守规则校验，可能拒绝本来正确的描述，也不能识别所有语义错误。原始标签和营养数据尚需进一步人工审核，不代表获得了医疗或营养效果验证。

## 3. 确认意图后展示结果，减少重复请求

对话每轮只发送一次完整请求，等待意图识别和结果生成后再展示卡片。明确要求推荐食材时，由规则锁定食材推荐，模型不会改成菜谱；问答、食材、菜谱分别展示对应结果。取消原有提前展示算法初选的方式，避免初选误判时先闪现无关菜谱。后端保留use_ai=false供离线联调使用；模型不可用时在本次请求内降级。

移除前端每步380毫秒和末尾420毫秒的模拟轨迹等待，展示实际返回流程。支持停止等待、页面关闭时取消请求，以及账号切换、取消后的迟到结果隔离。停止等待取消的是客户端请求，已经开始的服务端模型调用仍可能继续运行。

模型成功响应增加最多128项、默认300秒的进程内缓存。键包含完整模型输入、服务商地址、凭据和模型参数的摘要；条件变化不会误复用旧输入结果；响应使用深拷贝。失败不写缓存，命中时注明未再次调用模型。缓存不跨服务进程或重启共享。

交互模型调用增加默认18秒剩余预算控制，限制连续模型调用的等待。它不包含完整数据库、天气和网络各阶段的严格端到端时间保证；外部模型未能完成时保留算法结果。可通过AI_INTERACTIVE_BUDGET_SECONDS、AI_RESPONSE_CACHE_SECONDS配置。
