# 明确食材约束与多轮对话修复

问题：用户先要求 8 道菜，再说“只要鱼”，系统仍用牛肉、鸡肉补齐数量；模型文案甚至将这些额外菜解释为荤素搭配。

## 修改后的行为

- 将“只要鱼”“只推荐鸡肉”等明确要求保存为独立的食材硬约束，在召回和排序之前筛选。时令和整餐多样性不能覆盖该要求。
- 根据真实配料核对，区分鱼类与鱼香茄子、鱼露、鱿鱼、鲍鱼；排除混入其他肉类的菜。例如，只要鸡肉时不以含鸡爪的肉蟹煲充数。
- 数量、用餐人数、忌口继续分别保留；符合条件不足时如实返回较少数量，不放宽约束凑数。
- “换一批”继续遵守限制并避开已展示菜；“换成鸡肉”更新限制；“取消食材限制”解除包含条件，同时保留独立忌口。
- 新增条件时允许保留上一轮已展示的合适菜，避免去重误排除。明确要求推荐食材或菜谱时，卡片类型随当前要求切换。
- 严格限制场景下，模型只能在已过滤候选中选菜；不采用声称加入其他肉类的自由说明，展示可核对的结果文案。
- 页面“本次条件”显示限定食材，便于发现并纠正理解结果。

## 验证方法

先添加截图场景测试并确认失败，再完成修复。隔离测试涵盖数量继承、条件取消、名称误判、候选召回、模型选择越界、混合荤菜及食材/菜谱切换。

阶段性后端全量测试 490 项通过；随后补充的混合荤菜和入口切换相关回归 93 项通过。前端 53 项测试通过，静态检查无问题。另使用本地真实菜谱库测试连续对话，关闭 AI 调用，不修改库存或用户账号。

## 范围说明

这是对需求解析、条件状态和推荐约束执行的修复，不是重新训练模型。筛选依据仍是菜谱现有配料记录；记录缺漏时不能保证推断出未记录成分，也不将此功能作为过敏安全认证。鱼菜允许搭配蔬菜、豆腐等配料；“只要鱼”限定肉类来源，并不要求菜中只能有鱼这一种原料。
