# 会话条件优化

本次修改支持在聊天中明确表达人数、烹饪时间、清淡/少盐、忌口与不喝汤，并在后续请求中继续保留。

## 合并顺序

家庭档案或请求默认值 → 已保存的会话覆盖 → 本轮明确修改。新增/撤销忌口单独记录，撤销只影响会话，不写回家庭档案。汤羹作为排除品类保存。

时间支持数字或常见中文数字分钟、小时、一刻钟、半小时、一个半小时。超出1至20人或5至240分钟会要求用户重新说明，不执行推荐。

明确提出时间上限后，只保留有时间来源且不超限的候选；未知时长不能当作达标。候选为空不自动放宽时间，不自动重新加入已展示菜。单菜记录时长不证明整顿饭可以在同一时间内完成。

## 客户端

AI页展示后端返回的实际生效条件，提供“编辑条件”和“开始新会话”。会话覆盖、推荐意图及已展示ID按后端地址与账号保存在本机，刷新或重新打开可恢复；切换账号使用独立空间，旧账号在途回复不写入新账号。

后端保持无会话数据库依赖：请求携带conversation_state，响应同时返回conversation_state和effective_context。调用方还需携带last_intent与recent_recipe_ids/recent_food_ids。现有接口字段仍兼容。

这是结构化条件记忆，不是完整聊天记录或跨设备同步。浏览器禁止本地存储时仍可在当前页面连续对话。未配置AI或模型失败时，相同确定性解析和过滤仍会执行。

## 验证例子

1. 两个人晚餐，十五分钟，不吃花生，不喝汤。
2. 再换一组，其他条件不变。
3. 取消不喝汤，时间放宽到半小时，改成三个人，其他不变。

检查每轮的effective_context、excluded_categories与真实菜谱，并检查第三轮仍保留花生忌口。

本地改动未部署，不应将验证结果当成服务器当前状态。离线回归不调用真实模型，因此不证明模型生成解释的全部事实已得到验证。
