# 整餐搭配与菜单购物闭环

## 推荐

在已有忌口与时间筛选后，确定性组合搜索在最多24个候选中保留64条搜索路径，考虑素菜/蛋白类搭配、汤数量、同类主料及做法重复。配菜支持搭配均衡、快手、减少补购主料、多用现有食材四种目标；已有菜单参与组合判断，原有菜与排除菜不会重新推荐。模型只为最终允许组合选择和解释，不能重新放入被过滤的菜。

这是有限候选上的启发式组合，不证明全局最优或营养均衡。角色判断依赖现有标签与主料文字；补购统计只含已关联主料种类。已有单菜时长之和不等于整餐实际时间，没有虚构并行烹饪或厨具安排。

## 菜单

增删、单道替换自动保存到本机，按后端地址、账号、日期隔离。刷新恢复当天菜单，换日不混入昨日菜单，历史记录仍按日期保留。今日菜单可手动保存到云端或从云端恢复；服务端按账号和日期覆盖保存，非法菜谱会在更新前被拒绝。替换保留其余已选菜。

## 购物

在今日菜单选择是否抵扣库存，点击生成购物清单：先保存当前菜单，再从完整配料合并需求，抵扣明确库存，按类别展示并支持持久化勾选。更新菜单后需重新生成购物清单。

同食材使用food_id合并；没有ID才使用名称。克/千克/公斤/斤可统一为克，毫升/升统一为毫升；不把节、根、份随意换成克。数量未知的需求不会与已知数量混合成一个假精确值，也不会因为库存中有这个名字就整项删掉。默认“1份”等不明确库存不抵扣。生成清单不实际减少库存。

所有数量沿用原菜谱份量，人数尚未驱动可靠克重缩放。没有价格估计。离线可保留本机菜单，云端和真实购物清单需要连接后端并登录。

新接口：PUT /api/menu/today（recipe_ids、people、menu_date），GET /api/menu/today支持menu_date；现有购物生成、读取和勾选接口继续使用。使用现有菜单表日期字段，无新增数据库列。

## 本地验证

后端完整离线回归229项通过；前端完整回归29项通过，覆盖保存恢复、替换保留其他菜、账号/日期隔离、未知用量显示、离线不假报云端成功。Dart静态检查通过。测试未调用真实模型，未部署服务器。
