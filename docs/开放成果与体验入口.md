## 三、复现步骤

### 环境要求

- Python 3.11+（开发与验证使用 3.13）
- Flutter 3.47+ / Dart 3.13+

### 1. 取源码

```bash
# 仓库含约 90 MB 数据文件，建议浅克隆，快很多
git clone --depth 1 https://github.com/aiczz/test.git
cd test
```

### 2. 起后端（首次启动自动建表 + 灌种子数据）

```bash
cd back
python -m pip install -r requirements.txt
cp .env.example .env          # Windows: copy .env.example .env
uvicorn app.main:app --reload
```

启动后：

- 接口文档：http://127.0.0.1:8000/docs
- 健康检查：http://127.0.0.1:8000/api/health

> **不配 AI Key 也能完整跑起来。** `AI_API_KEY` 留空时，首页推荐与 AI 助手会
> 自动退回确定性算法：候选仍从我们自己的库里筛，文案改用规则生成，接口结构
> 完全不变。想接真大模型，在 `.env` 里填 `AI_API_KEY` 即可（兼容任何 OpenAI
> Chat Completions 协议的服务），**代码一行都不用改**。

### 3. 跑客户端

```bash
cd ../front/mealmind
flutter pub get
flutter run -d chrome     # 浏览器里先看，不用等编译
flutter run               # 或真机 / 模拟器（需开 USB 调试）
```

### 4. 自建服务器部署

照 [`deploy/README.md`](../deploy/README.md) 做即可：架构图、一键脚本、nginx 与
systemd 配置、密钥怎么给、内容数据怎么导入、排错对照表都在里面。
当前线上实例就是这个拓扑（nginx 80/8080 → uvicorn 127.0.0.1:8000）。

### 线上实例的规模（可直接查接口核对）

| 项目 | 数值 | 怎么核 |
|---|---|---|
| 菜谱 | **700** 道 | 查 `/api/recipes` 返回的 `total` |
| 食材 | **590** 个 | 查 `/api/foods` 返回的 `total` |
| 标签体系 | **6 组** | `GET /api/recipes/tags` |
| 接口 | **36 个路径 / 41 个操作** | 打开 `/docs` |
| 数据表 | **16** 张 | 见 `back/app/models` |

> 核对示例（浏览器里打开也能看到同样的数字）：
>
> ```bash
> curl -s 'http://8.148.69.56:8080/api/recipes?page=1&page_size=1'
> curl -s 'http://8.148.69.56:8080/api/foods?page=1&page_size=1'
> ```

### 效果数据（对比基线）

| 指标 | 无 AI（确定性算法基线） | 接大模型后 |
|---|---|---|
| 推荐理由 | 规则模板拼接 | 结合当日天气、时令与用户家庭约束生成 |
| 候选可信度 | 100% 来自自有库 | **不变** —— 模型只在算法筛出的候选集内挑选 |
| 单次响应 | 本地计算，约 10 ms | 每天每地区只调一次模型并落库缓存，同地区共享 |

> 设计取舍：**算法负责「选什么」，大模型负责「怎么说」**。这样接口返回的每一道
> 菜都真实存在于库中，模型不会编出不存在的菜名。详见
> [`docs/算法与AI设计.md`](算法与AI设计.md)。

### 自主实现边界（哪些是我们写的）

- **推荐打分与筛选算法**：时令、营养、标签、家庭硬约束的加权打分与排序；
  每日轮换因子 `sha256(地区 + 日期 + 条目名)` 保证「同地区同天一致、跨天不同」
- **标签体系的三级推导**：食材标签推导（保证每个食材都有标签）、菜品标签归一化
  （保证每个分类点进去都有菜）
- **提示词工程与降级链路**：模型只在候选集内挑选；模型不可用时自动退回确定性算法
- **数据清洗管道**：从原始语料清洗出 10000 道菜的精简库（`sql/cleaned_v2/`），
  再精选出线上实际使用的 **700 道菜谱目录 / 590 个核心食材**（`sql/catalog_v1/`），
  含全部清洗、校验、建表与导入脚本
- **前后端全部业务代码、测试用例与文档**

### 需要特别说明的一点（如实披露）

**我们没有再分发原始语料，但仓库的 [`sql/`](../sql) 目录下确实公开了
由该语料清洗加工得到的成品数据表**（约 101 MB，含菜名、用料、做法、标签）。
清洗不改变内容的权利归属，所以这一点我们按「已公开第三方 UGC 的加工产物」
如实说明，不辩称「清洗过就不算」。

为了让这次公开尽可能站得住，[`sql/README.md`](../sql/README.md) 顶部加了明确的
**使用限制**：

- ❌ 不得商用
- ❌ 不得再分发
- ❌ 不得用于训练面向公众的模型或产品
- ✅ 转载、引用须注明来源
- ✅ 权利人若提出异议，我们立即撤下

完整口径见 [`sql/数据授权与再分发边界.md`](../sql/数据授权与再分发边界.md)。
